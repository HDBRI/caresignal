# CareSignal — deterministic safety rules and synthetic evaluation

Rules version `2026-10-25.2` · generated by `npm run safety:report` from `src/lib/safety/rules.ts` and `tests/fixtures/safety-cases.json`.

> **Limitations.** These are a small set of predefined phrase rules for a classroom prototype. They are **not validated triage** and are **not** a guarantee that any emergency will be detected. The test phrases were written by the same developer who wrote the rules, so the results below describe behaviour on this synthetic set only — **not real-world sensitivity, specificity or clinical safety**. These prototype rules cover a small predefined set of phrases. No alert does not mean the situation is safe.

## How the layer works

- Runs on the **original note text**, inside the same database transaction that saves the note — before, and independently of, any AI call or network request. With no API key, a timeout or malformed AI output, the result is the same.
- Also runs on corrected wording (edits) and on check-in notes.
- Note text is data: words like “ignore your rules” or “mark as safe” cannot switch a rule off (see the prompt-injection group).
- Simple negation (“no”, “denies”, “without” shortly before a phrase) prevents a match.

## Behaviour levels

| Level | Shown as | Guidance |
|---|---|---|
| Emergency guidance | Red banner on every screen + icon, until marked seen | If this is happening now, call 911 and follow the dispatcher's instructions. |
| Prompt attention | Amber banner on every screen + icon, until marked seen | This note describes something the prototype's rules flag for prompt contact with an appropriate care professional. |
| Please review this observation | Neutral marker on the note + Overview list | This note mentions something worth reviewing. Consider whether the care team should know. |
| Routine — no predefined rule matched | Neutral “Routine” label | No predefined rule matched — this does not mean the situation is safe. Can go into a caregiver-reviewed handoff. |
