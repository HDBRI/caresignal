CareSignal

Evidence-linked, caregiver-reviewed handoffs from everyday care notes — with urgent safety guidance that never depends on AI.

What it doesCareSignal lets a family caregiver log observations in their own words, keeps every original note unchanged, shows rule-based urgent guidance immediately, and uses AI (gpt-6-luna) to organize the notes into an evidence-linked weekly handoff that the caregiver reviews before sending it to a simulated care team.
Classroom prototype. Synthetic data only — every person and event is fictional. Not medical advice, not a diagnostic or triage tool, not clinically validated, not HIPAA compliant, and not connected to any real EHR, clinic or care team. The safety rules recognize a small predefined set of phrases; no alert does not mean a situation is safe. In an emergency, call 911.
How to read this report (methodology). Real software behavior = what the running app actually did, captured from the app or its tests/logs on 2026-10-26. Synthetic content = fictional patients, notes and the scenario's prewritten "clinician response". Estimate = numbers derived from stated assumptions (only in Tokenomics). Tested on 2026-10-26: 348 unit/integration tests and 40 browser tests (including a final-audit suite), all passing, a 14-case deterministic evaluation, and one live 40-call model evaluation on synthetic notes. Unvalidated: real-world usefulness, time saved, clinical safety, and behavior on real caregiver language — no real users or patients were involved.

2. Motivation

Who has the problem. Family caregivers. Caregiving in the US 2025 (AARP & National Alliance for Caregiving) estimates about 63 million U.S. adults — one in four — provide ongoing care; over 40% provide high-intensity care, and only 22% report receiving training for the tasks they do [1]. Half report a negative financial impact and AARP cites about $7,200 a year in average out-of-pocket costs [1].

How they handle it today. Observations about eating, sleep, walking, mood or a worrying symptom live in memory, paper notes, family group texts, a journal site such as CaringBridge [5], a tracker app such as Bearable [4], or a portal message such as MyChart [3]. Before an appointment or a call, the caregiver has to reconstruct "what changed this week" from these fragments — often with several family members reporting different things.

What it costs. We did not measure caregivers' time or frustration (no user research was done). What is documented is that handoffs — transfers of information and responsibility — are a known failure point in care: AHRQ's patient-safety primer notes they "have been linked to adverse clinical events" and that structured formats such as I-PASS and SBAR exist for clinicians [2]. Family caregivers have no equivalent, honest structure for passing home observations to a care team, and a polished AI summary can make things worse if it hides uncertainty, invents facts, or delays urgent action.

What is genuinely new (in this prototype): the combination of (1) an evidence gate on every AI statement — exact quotes from the patient's own notes or the statement is dropped; (2) urgent guidance from fixed rules that run in the same database transaction that saves the note, before any AI call; (3) uncertainty, conflicting reports and "not reported" kept as first-class content; (4) a caregiver-approved handoff frozen as an exact snapshot with a SHA-256 fingerprint before delivery; and (5) longitudinal pattern detection that separates a single observation, a repeated pattern, timing after a documented treatment event, and uncertainty — without inventing severity scores or causes. Among the six tools we checked, none described this combination; that is not evidence that no such tool exists, and we make no "first" claim.

Standard or borrowed: LLM summarization with JSON-schema validation, keyword safety rules with negation handling, the structured-handoff idea from I-PASS/SBAR [2], symptom journaling, Postgres row-level security, idempotency keys and receipts. Why it matters: for a care conversation, a summary is only useful if a busy person can trust it — so it must show its sources, its gaps, and never stand between a caregiver and urgent guidance.

4. The agents

Honest framing. CareSignal is not a multi-agent system. There are no autonomous agents that plan, call tools on their own, or talk to each other. It is a server-orchestrated, sequential pipeline: two model-backed steps (both gpt-6-luna) and four deterministic components, each with one defined responsibility. The model never decides what runs next; application code does.

Figure 2 — Architecture. Solid boxes are deterministic code; dashed boxes are the two model calls. Arrows show the order the server runs them.

Model and why: gpt-6-luna via the course Portkey gateway — the only model the course key allows. Both steps request JSON and are capped; nothing the model returns is shown or stored before validation.

A real malfunction during the first attempt — and the fallback. In the first attempt of this run (17:21 UTC), the insight call hit the 20-second limit twice (timeout after 40.5 s including one retry). The app did not invent anything: the draft said "AI summary unavailable" and listed each note exactly as written, with a note that patterns and conflicts were not analyzed (Figure 3). We then raised the insight timeout to 60 s (the Insights page already tells users this takes 20–40 s) and the second attempt above succeeded in 17.7 s. The categorizer keeps its 20 s limit.

Pattern detection and the structured handoff (added 2026-10-26)

The Insights page now leads with "What appears to be changing": an overall picture, changes to pay attention to, patterns by category, a treatment/care timeline built only from events documented in notes, important uncertainties and questions. The weekly handoff is now structured — A. overall summary, B. key patterns by category (pattern, direction and timeframe, evidence as readable dates, documented event, uncertainty), C. important individual observations (incl. urgent notes), D. treatment timeline context, E. questions, F. evidence — and the simulated receiver shows exactly this submitted structure. The AI output contract is unchanged: patterns come from deterministic code, and the validated AI interpretations are shown separately. The case data has no structured treatment dates (only free-text milestones), so events are taken only from what notes document; a care_events table (date, kind, certainty, medication status: prescribed / caregiver-reported taken / unknown) is the proposed next data-model step.

Fix after the final audit. Rules version 2026-10-26.1. The final audit found that “not / isn’t / stopped breathing” was not covered and that a “not” in an earlier clause could cancel a later urgent phrase (“not breathing normally and won’t wake up” gave no alert). We added a pattern, limited negation to the same clause, and added 4 emergency phrases, 1 false-trigger probe and 2 negated phrases to the set. Known misses include “He was really out of it and I couldn't get him to talk”; known false positives include “Watched a documentary about chest pain.” The phrases were written by the same developer who wrote the rules, so these results describe this set only — not real-world sensitivity or comprehensive emergency detection.

Supporting views

8. Limits + next steps

What doesn't work yet / limits

  • Narrow safety coverage: a small predefined phrase set; 3 known misses and 2 known false positives on our own set; paraphrases outside it will be missed. Not triage.
  • Synthetic-only data written by the developer; no clinical validation; expected labels are the developer's judgement.
  • No real EHR or care-team integration — the receiver is simulated; not HIPAA compliant.
  • Depends on the model/API: AI features stop when the key, provider or daily cap is unavailable (notes, charts and safety rules keep working); we observed one real timeout and provider refusals (HTTP 400) on injection notes.
  • Model errors remain: 6/40 model cases failed; wrong category choices are not caught by validation; outputs vary between runs.
  • Small evaluation, one live run, no confidence intervals; no user research; price used for costs is unverified.
  • Pattern detection matches a small fixed set of themes in the caregiver's wording; other phrasings are missed; it was not part of the earlier live model evaluation. Treatment timing uses only events documented in notes — no structured treatment schedule exists yet.
  • Some screens (observation detail, older seeded handoffs) still show internal note IDs.

What we would build next

  1. A small, consented usability study with family caregivers (synthetic cases first): time to assemble a handoff, key facts kept, perceived clarity.
  2. Clinician review of the rule set and handoff format; broaden rules with clinician-written phrase lists and measure on an independent test set.
  3. Repeated evaluation runs (to measure model variability) and an independent labeler for categories.
  4. A real, consented delivery path (e.g., export to a portal message) only after privacy/compliance review.
  5. Multilingual notes and voice capture; verified pricing and per-user cost monitoring.
